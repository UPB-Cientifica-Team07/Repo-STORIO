R-02 - OpenLDAP sin TLS
Fecha: 2026-09-11

RIESGO ORIGINAL

OpenLDAP exponía LDAP plaintext en:

ldap://0.0.0.0:389
ldap://[::]:389

El Auth Service realizaba binds LDAP mediante:

ldap://127.0.0.1:389

Esto permitía que credenciales y consultas LDAP
se transportaran sin cifrado.

MITIGACIÓN

Se generó un certificado X.509 específico para LDAP
firmado por la CA privada de UPB-CIENTIFICA.

Certificado:

CN=localhost
OU=Directory
O=UPB-CIENTIFICA

SAN:

DNS:localhost
IP:127.0.0.1
IP:192.168.10.13
IP:192.168.10.18

OpenLDAP fue configurado mediante cn=config con:

olcTLSCertificateFile: /etc/ldap/tls/ldap.crt
olcTLSCertificateKeyFile: /etc/ldap/tls/ldap.key
olcTLSCACertificateFile: /etc/ldap/tls/ca.crt

Listener final:

SLAPD_SERVICES="ldaps:/// ldapi:///"

LDAP plaintext en 389 fue deshabilitado.

AUTH SERVICE

Default anterior:

ldap://127.0.0.1:389

Default nuevo:

ldaps://127.0.0.1:636

El cliente Java JNDI carga explícitamente la CA:

security/pki/upb_dev_ca.crt

Variable soportada:

LDAP_TLS_CA_FILE

DIRECTORY SERVICE

Los scripts:

bootstrap-directory.sh
provision-users.sh

utilizan por defecto:

ldaps://127.0.0.1:636

y validan la CA mediante LDAPTLS_CACERT.
